La sécurité, du code au conteneur

ÉTUDE DE CAS / ARCHITECTURE

Sécuriser la chaîne de conteneurisation.

PFA 2025–2026 réalisé avec Adam Elouardi, encadré par Dr. Loubna Chaibi à l’EMSI. Application support : Club Billard Elite, développée avec Django et PostgreSQL.

LIVRABLES / LIMITES

Une base construite, une industrialisation à poursuivre.

Le rapport confirme une application Django fonctionnelle, sa dockerisation, l’orchestration avec PostgreSQL et un utilisateur non-root. La présence d’un outil dans le dépôt ne constitue pas à elle seule une preuve de scan réussi.

  • Forcer DEBUG=False pour un environnement de production.
  • Supprimer les valeurs de secours sensibles pour SECRET_KEY.
  • Valider le workflow et générer les sorties dans reports/.
  • Configurer les secrets nécessaires à la publication Docker Hub.
  • Finaliser dashboards Grafana et alertes Prometheus.
  • Ajouter la signature d’image Cosign, non implémentée.

Source : rapport PFA, chapitre 10 « Résultats et état réel du projet », sections 10.2–10.3. Aucun taux de vulnérabilités corrigées ni résultat de pipeline non prouvé n’est ajouté.

01 / CONTEXTE

Le point de départ.

Club Billard Elite : intégrer des contrôles de sécurité au cycle de développement d’une application Django/PostgreSQL.

02 / OBJECTIFS & RÉALISATION

La démarche.

  1. Conteneuriser l’application avec un utilisateur non-root.
  2. Intégrer les contrôles SAST, d’audit de dépendances et de recherche de secrets au workflow ; son exécution réelle reste à valider.
  3. Analyser les images Docker et introduire le test dynamique.
  4. Mettre en place une première stack de monitoring avec cAdvisor.
03 / ARCHITECTURE

Les composants et leurs liens.

Code → GitHub Actions → Bandit / pip-audit / Gitleaks → Docker / Trivy → ZAP ; monitoring Prometheus / Grafana.
