01 / ÉTUDE DE CAS

Contexte et objectifs

TP Cloud Security, octobre 2026. Examiner des mauvaises configurations dans un environnement pédagogique, distinguer alertes et vulnérabilités confirmées, puis vérifier une correction.

02 / ÉTUDE DE CAS

Architecture

Terminal Linux / Nmap → Juice Shop dans Docker sur le port 3000 ; ZAP Baseline → application locale. AWS CLI / Prowler 5.44.0 → LocalStack 2026.9.1 → bucket S3 de test. Il s’agit d’une émulation locale, pas d’un audit AWS de production.

03 / ÉTUDE DE CAS

Reconnaissance réalisée

Le rapport documente un scan autorisé de scanme.nmap.org : 3 ports ouverts sur les 1 000 courants, 8 filtrés et 989 fermés. Un scan complet avec détection de versions est également rapporté. Ces observations historiques ne prouvent aucune vulnérabilité actuelle. Sur la cible locale, le port 3000 répond en HTTP avec le contenu OWASP Juice Shop ; l’étiquette de service incertaine de Nmap n’est pas une identification définitive.

05 / ÉTUDE DE CAS

S3 — réalisation et remédiation

Le bucket de test contient un objet de 49 octets. Les quatre paramètres PublicAccessBlock sont initialement activés ; aucune politique explicite de bucket, chiffrement par défaut AES256. Le TP les désactive volontairement, puis les réactive.

Contrôle ProwlerAvant correctionAprès correction
s3_bucket_level_public_access_blockFAIL / HighPASS

Désactiver PublicAccessBlock ne rend pas automatiquement l’objet public. Le résultat prouve la correction du contrôle vérifié dans LocalStack, pas la sécurisation complète d’un compte cloud.

06 / ÉTUDE DE CAS

Étudié / non revendiqué

La chaîne SSRF → métadonnées → stockage → exfiltration est un scénario théorique analysé, pas une exploitation réalisée. Les fiches IAM sont des supports d’exercice : aucune implémentation IAM supplémentaire n’est revendiquée sans compte rendu.
